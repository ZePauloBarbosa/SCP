Change street network provider?

You are switching this vendor's street network from OpenStreetMap (OSM) to Ordnance Survey (OS).

There is no migration path between the two. The street files are different, and streets present in one may be missing in the other. All travel paths will need to be regenerated, and any edits made to them will be lost.

SCP-5015 / SCP-5016 — what this mock shows
  • A new UK Street Data checkbox in Routeware Admin Features, third column, directly below UK Address Data and above Winter/Street Services — which is also the alphabetically correct position, so no ordering exception is needed.
  • No pencil / edit icon. The flag is on/off only; there is nothing to configure behind it.
  • Unchecked by default for every vendor. Visibility follows the section — the whole Routeware Admin Features block is already Routeware-employee only, so no extra gating.
  • ON → SmartCity tells FleetRoute to build the vendor's street network from Ordnance Survey (OS NGD) data. OFF → unchanged, OSM is used. Read at generation time; existing networks are not rebuilt.
  • Every change raises a confirmation modal — turning it ON and turning it OFF alike. There is no migration path between OSM and OS, so switching means all travel paths must be regenerated and any edits are lost. The modal is informational consent only: OK flips the flag and nothing else — it does not start, queue or schedule a regeneration.
  • The checkbox does not move until OK is pressed. Cancel, Escape, backdrop click and the ✕ all abandon the change and send nothing to the backend.
  • Checkbox uses the standard library component confirmed in Figma (Checkmark 48:4409): 15px box, 3px radius, #D9D9E1 border unchecked, #20315A fill checked, rgba(32,49,90,.4) checked-and-disabled.
  • Click the new checkbox to see both states. The dashed green outline and NEW tag are mock annotations only — they are not part of the build.
Functional reference only. All visuals must match the existing SmartCity Portal look and feel — use the standard components already in the portal, not this markup.
